- Sentinel Values / Flags / Indicators

-- This section is excellent for developing logic maturity.
-- Differences:

* Sentinel	- A special value that stops a loop (usually set by the user)
* Flag		- A boolean variable that tracks a condition (usually internal to the programmer)
* Indicator	- A variable showing state (e.g., found/not_found)

-- Example 1: Guessing Game

User continues entering guesses until they guess -1.

while guess <> -1

-- Example 2: Data Entry

Keep entering marks until user enters -1.

while intAge <> -1 // -1 is the sentinel value 


-- Questions to Ask Ourselves

* Why must sentinel values be chosen carefully?
* What if -1 is a valid input? and What if -1 is not a valid input?

* Searching

---

* When is a sentinel value better than a counter? 
- A sentinel value is used when the number of inputs or iterations is unknown, and the loop should stop when a specific value is encountered. A counter is used when the number of iterations is known in advance. 

* When is a flag better than a sentinel?
- A flag is better when you need to record whether a certain condition has occurred (e.g., a value was found or an error happened), rather than stopping the loop based on a specific input value like a sentinel. 

* Can you combine them?
- Yes, a sentinel can be used to control when the loop ends, while a flag can track conditions during processing (e.g., whether a specific value was found or a condition was met).

- The while..loop

-- Structure

Core Logic Pattern:

while [condition]
    {instructions} 
endwhile 

Emphasize:
A loop has **three required components**:

1. Initialization (before the loop begins)
2. Condition (the loop is dependent on this)
3. Update (we must affect change in order for the loop iteration to be valid or not)

Without one, we could likely cause a logical error.

-- Pre-test Behaviour

* Condition checked before execution
* May run zero times

Example:

while fltBalance > 0

// This loop might never be executed if the fltBalance is zero (0)

-- Primer Read

This is often confusing initially. We are expected to read the first value BEFORE the loop begins. The loop condition is dependent on that value that decides if the instructions inside the loop are going to be executed or not. 
 
input intAge 		// the primer read 

while intAge <> -1 	// -1 is the sentinel value 
	// process the age and anything else 
	input intAge 	// read the value again (we need to affect change to the loop iteration)
endwhile 

* Avoids duplicating read logic
* Ensures first value is checked

-- Logical Errors (Sentinel Inside Loop)

Classic beginner mistake:

* Sentinel not updated
* Infinite loop
* Off-by-one errors

Discussion:

* Why are infinite loops dangerous? 
- If the loop continues executing the instructions, it could lead to overusing resources. The program might crash unexpectedly. There might be other programs that need to be executed, but it cannot be, until the previous program ends.  

* When might infinite loops be intentional? (servers, operating systems)
- There is some processing that needs to be repeated continuously

* Runs at least once

-- Differences from while

| while           | do..while              |
| --------------- | ---------------------- |
| Pre-test        | Post-test              |
| May not execute | Executes at least once |

-- Sentinel Selection Pitfalls

These questions are being shared here, but have been dealt with in the above program versions/variations/ 

* What if user inputs the sentinel first?
* What if sentinel is a valid data value?

- Sentinel values must be:
* Outside valid input range
* Clearly communicated to users

Our program code, the order of instructions, the logic needs to be adapted to meet the needs of the storyline. If and when the storyline evolves, our program code must evolve with it.

Example

- The computer generates a random number between 1 and 10 (inclusive).
- The user attempts to guess the number.
- After each guess, the program must provide feedback:
  - “Too High!” if the guess is above the number
  - “Too Low!” if the guess is below the number
  - A success message if correct

FINAL SUMMARY
=============

1. Programs are built incrementally
   - start simple
   - add one concept at a time
   - avoid designing full complexity immediately

2. Variables represent state
   - intGuessCount → tracks interaction history
   - intFlag → controls loop termination
   - strPlayAgain → controls program-level repetition

3. Loops are not interchangeable
   - while → condition checked first
   - do..while → guaranteed execution first

4. Real systems are layered
   - input handling
   - decision logic
   - repetition control
   - session control

5. Nested loops represent system structure
   - inner loop = task repetition (guessing)
   - outer loop = session repetition (playing again)

6. Design matters more than syntax
   - same problem can be solved in multiple valid ways
   - correctness depends on logic placement, not just keywords

-- Loop Condition Handling

The development of the condition for a while..loop and a do..while loop is an important choice. In both cases, the result of the condition dictates the repetition(true) or the exit(false) of the loop. 

If the storyline is: 
- dependent on the user's input, then a sentinel value will be used. 
- dependent on the number of times that the instructions need to be executed, then a counter variable will be used.
- dependent on actions of the program, something that is likely decided internally, then a flag variable will be used.  

* It is important to remember the common tasks, specifically counting (using incrementing or decrementing), depending on what we are counting, we must be aware of the "off-by-one error", a possible logical error that could occur if the order of instructions are not performed correctly. 

* The conditions are never only just 1 variation. There are times when a compound condition will aid in dealing with multiple decisions that are apart of the storyline.

-- Logic of a Loop

This is the most important conceptual section.

Every loop contains:

1. Initialisation
2. Condition
3. Update

If any one is wrong → logic fails.

- Before running a loop, students should ask:

* Where does my loop start?
* When does it stop?
* What changes each iteration?

-- Big Idea to Emphasize

Loops are not about syntax.

They are about:

* Control
* Structure
* Prediction
* Designing repeatable processes

// B 

0. Start
1. Declarations 
	num fltPrice, fltWholesalePrice  
	num intDay 
	num fltDiscount = 0.1 

2.	output "Enter the original price of the item: R" 
3.	input fltPrice 

4.	output "Enter the wholesale price of the item: R" 
5.	input fltWholesalePrice 

6.	for intDay = 1 to 5 Step 1 
		fltPrice = fltPrice - (fltPrice * fltDiscount)
		if fltPrice < fltWholesalePrice then // if the calculated discounted amount falls below the wholesale price 
			fltPrice = fltWholesalePrice // set the current price to the wholesale price 
		endif 
		output "Day " + intDay + " = R" + fltPrice 
	endfor 
7. Stop
