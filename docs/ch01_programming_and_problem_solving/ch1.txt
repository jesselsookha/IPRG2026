-- Hardware 
- Hardware is **physical and touchable**.
- Hardware does nothing on its own — it needs instructions (software).
- Hardware is designed around one goal: **processing instructions as efficiently as possible**.

The CPU has:

- Control Unit (directs traffic)
- Arithmetic Logic Unit (ALU – performs calculations)
- Registers (tiny, ultra-fast memory inside CPU)

Q. What happens if you install high-end software on weak hardware?
A. You will discover:
- Slow performance
- Freezing
- Crashing

This leads to discussions about **hardware limitations** and performance bottlenecks.

-- 6 Steps Problem Solving 
*Programming is 70% thinking, 30% typing.

1. Identify the problem (what is being asked?)
2. Understand the problem (inputs? outputs? constraints?)
3. Identify alternative solutions to solve the problem 
4. Select the best way to solve the problem from the list of alternative solutions (efficiency matters)
5. Write the algorithm (List the instructions that enable you to solve the problem using the select solution)
6. Test & Evaluate the solution (find logic errors)

-- Algorithms / Flowcharts 
- algorithms - instructions 
- a clear series of steps 
- must have a begin & end (Start / Stop) - finite - must start and must stop 
- effective in completing tasks
- input (accept value from user) & output (display result or prompt to ask user to input)

- the order of instructions 
- numbering instructions will begin at 0. - helps to read the coded instructions 

- each instruction performs one action 
- indentation is important to implement, view & read code 	
- no punctuation 
- naming of variables 

Example: 
0. Start 
1.	input number 
2. 	answer = number * 3 
3.	output answer 
4. Stop 

	
- flowcharts - visual representation of the algorithm 
- use Office 365 - Visio or draw.io (some shapes need to be customized a little)

- rules - single entry / exit  
- symbols 
- rectangle - processing - calculations 
- rounded rectangle - start / stop 
- parallelogram	- input / output 

- flowlines 
- connect shapes to help visualize the flow of the program from start to end 
- top-down flow is default & noted in example shown in class
- we will label the flowlines when the time comes in future chapter work

- other 
- diamond - decisions + loops (single entry - multiple exits, but only one exit will be recognized based on the result of the decision)
- hexagon - specifically for the for loop 
- rectangle with 2 lines - sub-processes / functions / procedures 
- circle - used to end a for loop + its also an on-page reference 
- upside down house - off-page reference
