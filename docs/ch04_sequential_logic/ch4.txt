CHAPTER 4 — Sequential Logic

- Sequential Logic Structure

Sequential logic is the simplest control structure in programming.

It means:
-- Instructions execute one after another, in the exact order they are written — from top to bottom.

There are:

* No decisions
* No repetition
* No jumping around

It is the default mode of a program.

-- Analogy

- What happens if you brush your teeth before putting toothpaste on the brush?

or:

- What happens if you bake a cake before mixing the ingredients?

** A recipe
the method 	- important to remember the right ingredients and the order that needs to be followed to bake the cake 
algorithm  	- everything we learnt in Chapter 2 is presented in the form of an algorithm 


Life itself is sequential.

Programming simply formalizes something they already understand.

-- Core Components of Sequential Logic

Most sequential programs contain:

1. Input
2. Processing
3. Output

** Remember the IPO Model in Chapter 1 

Input → Process → Output

This becomes the mental template for every program you write.

-- Program Flow

In sequential logic:

* Execution starts at the first line
* Continues downward
* Stops at the last line

	START
  	↓
	Step 1
  	↓
	Step 2
 	↓
	Step 3
  	↓
	STOP

-- Relationship to More Complex Structures

Sequential logic is the foundation for:

* Selection (if..then, if..then..else)
* Repetition (while, do..while, for)
* Functions / Procedures
* Object-oriented design

** “Every complex program is just sequential logic — plus control over which steps execute and how often.”


? If a program only uses sequential logic, what can’t it do?
	- It cannot make decisions
	- It cannot repeat tasks automatically
	- It cannot respond differently to different inputs

-- Order Again 

** Remember the program that calculated the total hours and minutes that an employee worked in a day 

// original code that we coded
intHours = (intNoonOut - intMorningIn) + (intNightOut - intNoonIn) \ 60 
intMins = (intNoonOut - intMorningIn) + (intNightOut - intNoonIn) MOD 60 

// edited - total minutes is first calculated 
intTotalMins = (intNoonOut - intMorningIn) + (intNightOut - intNoonIn)

// hours and minutes are now calculated as before 
intHours = intTotalMins \ 60 
intMins = intTotalMins - (intHours * 60)

// what if we make the mistake of attempting the calculate the minutes before the hours 
// note the use of the intTotalMins variable and now what is this order incorrect 
intTotalMins = (intNoonOut - intMorningIn) + (intNightOut - intNoonIn)
intMins = intTotalMins - (intHours * 60)
intHours = intTotalMins \ 60
