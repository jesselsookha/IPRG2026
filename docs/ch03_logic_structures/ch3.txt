Chapter 3 - Logic Structures 

- Spaghetti Code

-- What is Spaghetti Code (Beyond the Definition)?
-- Spaghetti code is not just “messy code.” It’s code where:
	- Control jumps around unpredictably
	- Logic is tangled
	- Small changes break other parts
	- No clear beginning or end to sections

It often happens when:
- Beginners keep adding features without redesigning
- Deadlines are rushed
- No planning was done (no pseudocode, no flowcharts)
- Copy–paste programming

---

- Simple Example

Bad structure:

Start
input number
if number > 0
    print "Positive"
go to EndCheck
if number < 0
    print "Negative"
EndCheck:
print "Done"
Stop

Thinking: 
- Why is there a jump?
- What if we add more conditions?
- How many labels will we need? What is the purpose of the labels? 

- Prevention Steps against Spaghetti Code 
	- comments
	- understanding the code base 
	- perform unit tests  
	- use light frameworks 
	- always double-check 

** Read the Manual to get a complete understanding

- Three Basic Logic Structures

All programs — no matter how complex — are built from only three structures.

- Sequential Logic
-- All instructions are executed in the order that it has been written - in sequence 
-- It is:
	- The default
	- Straight-line execution
	- Top to bottom

It’s predictable.

- Analogy

Following the method to bake a cake. 
You can’t rearrange those randomly.

- Example
0. Start 
1. Declarations
	num fltLength
	num fltWidth
	num flttArea
 
2.	input fltLength
3.	input fltWidth
4.	fltArea = fltLength * fltWidth
5. 	output fltArea
6. Stop 

- Decision Logic

-- Decision logic introduces:
	- Choice
	- Branching
	- Different paths

- This is where programs become dynamic.
- The question is presented in the form of a logical expression; depending on the result, a path of execution is then decided 

-- Analogy

Traffic light:
	- If green → go
	- If red → stop
	- Else → prepare

-- Introduced to 2 new coding structures 
	- if..then 
	- if..then/else 
-- Example

    		output "Pass"
	else 
    		output "Fail"
	endif 

?.	if intMark >= 75 then 
    		output "Distinction"
	else 
		if intMark >= 50 then

			output "Fail"
		endif 
	endif

	- Controlled by conditions

	Structured programs:
	- Are readable
	- Communicate intent
	- Reduce mental load

-- Maintenance

- Recognising Structure Issues

-- Flowchart Layout
	- Clean top-to-bottom flow
	- No unnecessary diagonal lines
	- Clear branches

-- Single Entry / Single Exit
	A structure should:
	- Start at one point
	- End at one point

	Bad practice:
	- Multiple random exit points

-- Avoid Crossing Flowlines
	Crossed lines in flowcharts usually mean:
	- Poor planning
	- Overlapping logic
	- Potential spaghetti code
